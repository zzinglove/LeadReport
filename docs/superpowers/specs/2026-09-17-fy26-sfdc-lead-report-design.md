# FY26 SFDC Lead 웹 레포트 설계안

## 1. 목적과 범위

현재 PPT 레포트의 분석 체계를 웹 레포트로 전환한다. 관리자가 Salesforce에서 내려받은 전체 Excel을 업로드하면 검증과 미리보기 후 승인된 스냅샷을 생성하고, 최신·과거 기준일의 주간·월간·누적 지표를 제공한다.

이번 설계의 범위는 다음과 같다.

- PPT의 모든 주간·월간 요약 지표를 초기 히스토리로 반영
- Excel 업로드별 원본 스냅샷 및 집계 결과 보존
- `Created Date` 기반 주간·월간 집계
- `Main Interest Area`를 `관심제품`으로 저장하고 Business 파생
- 별도 초대 계정 인증
- `Organization Level 2` 기반 원본 Lead Data 접근 제어
- 전체 공개 집계와 권한 제한 원본 Drill-down 분리

## 2. 사용자와 권한

### 역할

- 시스템 관리자: 모든 조직의 집계·원본 데이터 조회, 사용자 초대·비활성화, 조직 권한 지정, Business 매핑 관리, Excel 업로드 및 반영
- 일반 사용자: 기본적으로 하나의 `Organization Level 2` 권한
- 본부장·부문장: 여러 `Organization Level 2` 권한을 가질 수 있음

### 접근 원칙

- 로그인한 모든 사용자에게 Overview와 모든 부서의 Summary 집계 수치를 공개한다.
- 집계 화면 안에서도 부서별 수치는 공개한다.
- 집계 수치를 클릭한 원본 Lead Data Drill-down은 요청된 행의 `Organization Level 2` 권한을 서버에서 검증한다.
- 권한이 없는 타 조직의 원본 행은 일부 필드를 가린 형태를 포함해 반환하지 않는다.
- 타 조직 원본 데이터의 API, 검색, 다운로드, 상세 URL도 차단한다.
- 시스템 관리자는 전 조직 원본 데이터를 조회할 수 있다.

## 3. 데이터 구조

### 핵심 엔터티

- `users`: 이메일 로그인 ID, 계정 상태, 역할, 비밀번호 상태
- `user_org_permissions`: 사용자와 허용된 `Organization Level 2`의 다대다 관계
- `lead_snapshots`: 승인된 업로드의 기준일, 업로드 시각, 상태, 원본 파일 메타데이터
- `leads`: 스냅샷별 Lead 원본 행. `SFDC_Lead_Code`와 snapshot 관계로 식별
- `business_mapping`: `관심제품`과 `Business`의 매핑
- `historical_metrics`: PPT 초기 데이터 및 스냅샷별 계산 결과
- `upload_drafts`: 검증 통과 후 관리자 반영 전의 임시 업로드와 미리보기 결과

### 원본과 DB 컬럼

Excel 원본 컬럼명은 업로드 검증과 추적을 위해 매핑 정보에 보존한다. DB 컬럼명은 사용자 확정 명칭을 사용한다.

현재 확정된 매핑은 `요구정의.md`의 4.4절을 단일 기준으로 한다. `Lead Owner: Role: Name`과 `Converted Account: Site: Name`은 저장·집계에서 제외한다.

`Business`는 Excel 원본 컬럼이 아니라 `관심제품`을 기준으로 파생한다.

## 4. Excel 업로드 흐름

1. 관리자가 전체 Excel 파일을 업로드한다.
2. 파일 형식과 필수 컬럼 15개를 검증한다.
3. `SFDC Lead Code`가 없고 Lead 필드가 비어 있는 Salesforce 푸터 행을 제외한다.
4. `관심제품`의 모든 값이 Business 매핑에 존재하는지 검증한다.
5. 검증 실패 시 파일을 운영 데이터에 저장하지 않고 누락 컬럼, 변경 컬럼 또는 미매핑 상품명을 표시한다.
6. 검증 성공 시 임시 `upload_draft`를 만들고 행 수, 기간, 상태별 건수, Business별 건수, 주요 증감 미리보기를 표시한다.
7. 관리자가 `반영`을 클릭할 때만 스냅샷과 집계 결과를 운영 데이터에 저장한다.
8. 반영하지 않은 임시 업로드는 운영 리포트와 기존 스냅샷에 영향을 주지 않는다.

같은 날짜에 여러 번 반영하면 해당 날짜의 마지막 반영본만 유효하게 사용한다. 이전 반영본은 기준일 선택 대상과 최신 집계에서 제외한다.

## 5. 기준일과 보관

- 기준일은 Excel 반영 날짜를 Asia/Seoul 기준으로 자동 생성한다.
- 기준일 선택기는 실제 유효 스냅샷이 있는 날짜만 제공한다.
- 선택한 기준일에는 해당 날짜의 마지막 반영 스냅샷을 표시한다.
- 최근 2년 이내 스냅샷은 날짜별로 보관한다.
- 2년이 지난 스냅샷은 각 연·월의 가장 빠른 날짜 스냅샷 1개만 유지한다.
- 대표 날짜에 반영본이 여러 개면 그 날짜의 마지막 반영본을 유지한다.
- 정리 작업은 보존 대상 스냅샷을 확정한 후 나머지를 삭제한다.

## 6. 집계와 화면

### 집계 기준

- 주간: 월요일~일요일
- 월간: `Lead생성날짜`의 연·월
- 상태: 선택한 스냅샷 시점의 `Lead상태`
- Business: `관심제품`의 매핑 결과
- 상세 Drill-down: 선택한 집계 조건과 `Organization Level 2` 권한을 모두 적용

### 화면

- Overview: 기준일 선택, 전체 핵심 KPI, 전주·전월 비교
- Weekly: 주차별 Lead·상태·전환율·Source·Business
- Monthly: 월별 유입·상태·전환율·Business 추이
- Organization: 전체 공개 부서 Summary, 권한 기반 원본 Drill-down
- Pipeline: Opportunity 상태·GI·매출·Won/Lost/On-going
- Source & Product: Lead 유입경로·관심제품·Business
- History / Upload: 유효 스냅샷 날짜, 업로드 미리보기, 반영 이력

## 7. 초기 PPT 히스토리

PPT에 포함된 모든 주간·월간 요약 수치를 `historical_metrics`에 입력한다. PPT 기준일과 Excel 최신 기준이 다를 수 있으므로 초기 PPT 데이터에는 출처와 기준일을 표시한다.

PPT에 없는 과거 Excel 원본 행 단위 상세는 생성하지 않는다. 웹 오픈 후 승인된 Excel 스냅샷부터 행 단위 상세를 제공한다.

## 8. 보안 설계

- 이메일 주소를 로그인 ID로 사용한다.
- 초대 사용자는 최초 로그인 시 비밀번호를 설정한다.
- 비밀번호 분실 시 이메일 재설정 링크를 사용한다.
- 원본 행 조회 API는 세션의 사용자 역할과 허용 조직을 서버에서 검증한다.
- 클라이언트에 전체 원본 데이터를 먼저 내려보낸 뒤 화면에서 숨기는 방식을 사용하지 않는다.
- 다운로드도 동일한 조직 권한 검증을 통과해야 한다.
- 사용자·조직 권한 변경은 다음 요청부터 적용한다.

## 9. 오류와 검증

- 필수 컬럼 누락 또는 컬럼명 변경: 업로드 거부 및 오류 컬럼 표시
- 미매핑 상품명: 업로드 반영 중단 및 Business 매핑 등록 안내
- 빈 `SFDC Lead Code`가 있는 실제 Lead 행: 검증 오류로 처리
- Salesforce 푸터 행: Lead 필드가 비어 있으면 자동 제외
- 데이터가 없는 기간: 0으로 임의 보정하지 않고 데이터 없음으로 표시
- 권한 없는 원본 조회: 서버에서 거부하고 원본 행을 반환하지 않음

## 10. 검증 계획

- 필수 컬럼·푸터 행·미매핑 상품 검증 테스트
- 동일 날짜 마지막 반영본 선택 테스트
- 기준일 목록이 유효 스냅샷 날짜만 포함하는지 테스트
- 주간 경계가 월요일~일요일로 계산되는지 테스트
- Business별 집계가 매핑표와 일치하는지 테스트
- 전체 공개 Summary와 권한 제한 원본 Drill-down의 분리 테스트
- 일반 사용자·복수 조직 사용자·시스템 관리자의 API 접근 테스트
- 2년 초과 스냅샷 월별 보존 정책 테스트

## 11. 미확정 사항

- 시스템 관리자 계정 수와 관리자 운영 방식
- 초대 이메일 문구와 링크 유효기간
- 배포 환경과 접근 URL
